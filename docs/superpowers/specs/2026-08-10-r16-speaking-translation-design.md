# R16｜口语反馈显示目标表达中文翻译

日期：2026-08-10  
状态：设计已获用户口头批准，等待书面规格确认

## 1. 目标

用户完成一题口语录音并进入反馈后，在既有“目标表达”英文下方显示该目标表达的准确中文翻译，帮助用户理解正确表达。

R16只补充课程目标表达的中文翻译，不翻译语音识别文本，不改变口语内容匹配、录音、回放、计时、错题或评分规则。

## 2. 显示规则

1. 录音前不显示中文翻译，避免提前暴露学习答案。
2. 完成录音并进入反馈状态后，在“目标表达”英文下方显示“中文翻译”。
3. “实际识别”继续只显示语音识别得到的英文，不提供中文翻译。
4. 语音识别失败、没有可用识别文本或本题不可评分时，只要已经进入录音后的反馈状态，仍显示目标表达及其中文翻译。
5. 不可评分状态必须继续明确显示“本题无法评分”或现有等价提示，中文翻译不得被误解为评分结果。
6. 日常口语、R6不限时额外口语和统一错题库中的口语原题复习遵守同一显示时机与内容规则。

## 3. 内容规则

1. 每一道正式口语提示必须具有与目标表达对应的正式中文翻译。
2. 中文翻译由课程内容预先编写并随课程资源离线发布，不在运行时调用AI、机器翻译或外部服务。
3. 现有`cueZh`是任务提示，不等于目标表达翻译，不得直接冒充翻译。
4. 翻译以该题的正式`modelAnswer`为对象。其他可接受英文表达不需要逐条生成不同翻译。
5. 翻译必须忠实、自然，并保留姓名、地点、时间、金额、电话号码等题目关键信息。
6. 缺少翻译、空翻译、翻译与目标表达身份不匹配或课程资源漂移时，内容校验必须失败，不允许悄悄隐藏字段后发布。

## 4. 模块边界

### 05｜课程内容

- 为全部正式口语提示补充目标表达中文翻译。
- 扩展并校验课程内容结构。
- 确保日常供应、额外训练和错题复习引用同一正式翻译事实。

### 08｜口语训练

- 在公开口语提示与反馈模型中传递正式中文翻译。
- 保持现有录音、识别、内容匹配、不可评分降级和错题证据逻辑不变。
- 不自行翻译英文，也不根据识别文本生成中文。

### 02｜UI / UX

- 只在反馈状态的“目标表达”区域显示“中文翻译”。
- 保持目标英文、中文翻译、实际识别英文三者的标签和视觉层级清晰。
- 不在录音前显示翻译，不把翻译显示成评分或纠错结论。

### 01｜应用集成

- 将新增内容字段接入正式课程加载、路由、恢复、构建和PWA离线资源。
- 确保日常、额外训练和错题复习入口使用同一正式数据。

### 09｜验收

- 覆盖正式URL、30秒测试模式、iPhone入口、刷新恢复和离线重开。
- 分别验证可评分、识别失败但录音可回放、完全不可评分三种反馈状态。

## 5. 数据流

正式课程中的目标表达和中文翻译一起进入口语内容解析器；08把两者作为只读事实传给口语反馈视图模型；02只按反馈状态渲染；01负责生产资源、恢复和离线集成。任何模块都不得在运行时重新翻译或猜测缺失内容。

## 6. 错误处理

- 内容缺少正式翻译：构建或课程校验失败，不发布不完整版本。
- 识别失败：保留录音回放与不可评分提示，正常显示目标翻译。
- 课程身份漂移或损坏：沿用现有诚实错误与恢复流程，不使用旧题提示或临时翻译填补。
- 离线状态：翻译来自PWA预缓存的课程资源，不依赖网络。

## 7. 验收标准

R16只有在以下条件全部满足后才能关闭：

1. 所有正式口语提示均有通过校验的目标表达中文翻译。
2. 录音前不显示翻译，录音后反馈显示翻译。
3. 可评分和不可评分反馈均遵守相同披露规则。
4. 实际识别文本不被翻译，不增加发音、口音或流利度评分。
5. 日常口语、额外口语和错题复习口语题全部接通。
6. 类型检查、全量测试、课程校验、生产构建和PWA预缓存通过。
7. 正式URL与30秒测试版通过自动化验收。
8. 用户在实际入口确认显示内容和时机正确。

R16完成前不得自动启动R5、QA-R11-UX-001或R15。
